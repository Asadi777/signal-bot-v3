## 3. The one thing that could not be done

Every exchange host is blocked by the egress policy of the environment this
work was done in. `data.binance.vision`, `api.binance.com` and `api.bybit.com`
all answered `403` at the CONNECT stage. Nothing was retried or routed around.

Consequences, stated plainly:

- **No source is verified.** All 17 Data Source Matrix rows are `UNKNOWN`. This
  is the correct output, not a placeholder: the validator refuses `AVAILABLE`
  without all seven evidence items, and no evidence could be collected.
- **No real market data was fetched**, so the sample dataset is synthetic.
- **The collectors are unexercised against live responses.** Their parsing is
  covered by tests built from the documented payload shapes, which is not the
  same as having seen the real thing.

What this does *not* block: the pipeline itself is fully exercised. The offline
run uses the same collector code against the same archive layout over
`file://`, so pagination, checksum verification, resume, idempotency,
determinism, schema validation and the quality report are all genuinely tested.

To finish Phase 0A, one run in an environment with egress to those four hosts
is required. `make live-verify` is written to produce exactly the evidence the
matrix rows are missing.

## 4. Sample dataset

`research/sample/` holds eight partitions, the data-quality report and one run
manifest. The data is synthetic and generated by `prepump.fixtures`. That is
deliberate on two counts: it keeps the sample reproducible from code, and it
sidesteps the redistribution question entirely, since no exchange data is
committed anywhere in this repository.

The generator injects the defects the report is supposed to find: a duplicated
candle, an OHLC violation, zero-volume candles with a non-zero price range, a
sparse symbol that is mostly no-trade minutes, one multi-hour hole, and a
symbol whose series stops mid-month to stand in for a delisting. The committed
report finds all of them.

## 5. Findings worth carrying forward

**A missing minute is usually not missing data.** Exchanges emit no candle for
a minute with no trades. Treating every such minute as loss would have buried
real collection gaps under millions of false alarms — on the synthetic thin
symbol, 35% of minutes have no candle and essentially all of it is normal.
Gaps are classified by run length and never filled.

**Timestamp units are not stable across archive files.** Binance kline dumps
have shipped time columns in seconds, milliseconds and microseconds. The parser
detects the unit per file and records what it found; assuming one would shift
every candle by three orders of magnitude with nothing downstream noticing.

**Resume and revision detection are in tension.** A resumed run cannot know the
source has revised a file without downloading it again, which is what resume
exists to avoid. The chosen contract: resume trusts the recorded revision, and
a periodic `--no-resume` run is what catches upstream revisions. Documented in
`docs/decisions/0001`.

**`available_at` for archive data is derived, not measured.** It is candle
close plus a documented delta, carrying an explicit method and uncertainty on
every row. A measured availability time needs a live websocket collector, which
Phase 0A does not build. Nothing here supports sub-second availability claims.

**Spot listing dates do not exist at the source.** Binance spot `exchangeInfo`
has no listing date, futures has `onboardDate`, Bybit has `launchTime`, and
delisted symbols vanish from all three. The only membership history these
endpoints can give is a series of dated snapshots — which is why that cadence
should start on day one of the live run, not when it is needed.

## 6. Limitations and open questions

1. Everything in §3: nothing is verified against a live source.
2. Bybit's real 1-minute historical depth is unknown. `probe-bybit-depth`
   measures it; if it is shallow, Bybit's role in Stage A shrinks and that
   becomes a recorded gap rather than a silent omission.
3. Whether the archive genuinely retains delisted symbols is the single
   assumption the survivorship rule rests on, and it is untested.
4. The delisted candidates in the smoke universe (`SRMUSDT`, `ANCUSDT`,
   `MIRUSDT`) are unverified guesses at symbols that were removed. If they were
   not, they need replacing with symbols that were.
5. Distinguishing "no trade" from "collection gap" with certainty needs
   trade-level data. The middle band of gap lengths is labelled unclassified
   rather than guessed.
6. Storage projections in the plan (~3 GB for the smoke set, ~150 GB for a full
   universe over five years) are arithmetic, not measurement.
7. The three P0 gaps in `docs/decisions/0004` — prediction sampling policy,
   feature embargo, alert budget — still block Stage A from producing
   interpretable numbers.
8. Open decision in `docs/decisions/0002`: are taker-side columns Stage A or
   Stage C?

## 7. Recommended next task

In order, smallest first:

1. **One network-enabled run** of `make live-verify` and `make live-metadata`.
   This turns matrix rows into evidence and answers items 2, 3 and 4 above. It
   is the whole remaining cost of finishing Phase 0A.
2. **Start the metadata snapshot cadence immediately** (daily). Every day not
   collected is membership history that cannot be recovered afterwards.
3. **Backfill the real smoke universe** for a 3-month window and compare the
   quality report against the synthetic one. Expect the surprises to be in gap
   structure on thin symbols.
4. **Decide the three P0 items** in `docs/decisions/0004`. They are cheap to
   decide now and expensive to retrofit after Stage A has run once.
5. Only then: the Pump Event Label and Onset Detector v0, per the Feasibility
   Charter's WP1.

Explicitly *not* recommended yet: any model, any feature engineering beyond
what the label work requires, any frontend, any n8n workflow, and any paid data
subscription.
